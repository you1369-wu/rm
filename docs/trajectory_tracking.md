# 云台目标轨迹跟踪：接入、操作与答辩说明

## 1. 本次实现与适用条件

基于 `you1369-wu/rm_yuntai` 的 `fc4d964d67fe79840ae3f027f09168f7d2ac0b17`，
中间件版本 `0d56d8417fad044f64b3d2e68151c8ec25a5b5b7`，
开发分支 `feat/trajectory-tracking`。A（GM6020 ID 1）对应 yaw，
B（GM6020 ID 2）对应 pitch，此轴对应关系已由使用者确认。

本实现包含四项要求：

1. 独立 `trajectory_task` 以 1 ms 周期运行组委会轨迹，`control_task` 以 1 ms 周期消费目标。
2. 角度 P 外环、速度 PI 内环、速度前馈，以及默认关闭的加速度/重力前馈。
3. `plot_task` 输出两轴目标、实际、误差、速度、力矩、RMS、运行状态等 18 通道。
4. 本文给出结构、参数单位、整定流程、限幅原理、故障含义及改进方向。

轨迹角度定义为**相对于标定机械零点的关节角度**，反馈来自电机编码器。
它适用于基座固定的 yaw/pitch 跟踪；若比赛要求“运动基座下的世界坐标视线角”，
必须增加坐标变换和惯性反馈，不能直接把本实现当作惯性稳定云台。
原工程的 IMU 联动、复位模式继续保留。

## 2. 文件与数据流

| 文件 | 作用 |
| --- | --- |
| `applications/trajectory_task.cpp/.hpp` | 附件中的 681 点表、插值和缩放接口；增加等待/启动握手 |
| `applications/trajectory_runtime.hpp` | 一致性快照、时间戳、相位和启动接口 |
| `applications/tracking_config.hpp` | 电机映射、标定零点、方向、行程、控制参数和超时阈值 |
| `applications/tracking_controller.cpp/.hpp` | 可独立测试的串级控制核、条件积分、五次启动曲线 |
| `applications/tracking_mode.cpp/.hpp` | 对齐→等待→播放状态机、保护和统计 |
| `applications/control_task.cpp` | 模式选择、反馈快照、唯一 CAN 输出 |
| `applications/tools/plot_task.cpp` | USART1 二进制绘图输出 |
| `applications/usart_task.cpp` | 保留 CubeMX 入口，停止原 IMU 文本输出，避免串口混帧 |
| `Core/Src/freertos.c` | 在 USER CODE 区静态创建轨迹与绘图任务 |
| `Core/Inc/FreeRTOSConfig.h`、`rm_imu.ioc` | 开启 `vTaskDelayUntil` |
| `CMakeLists.txt` | 添加新增 C++ 源文件 |
| `tests/` | 使用实际轨迹源与控制代码的主机逻辑测试 |

```text
组委会轨迹表 --trajectory_task--> 带时间戳快照
                                     |
编码器反馈 --短临界区快照--> control_task：模式状态机
                                     |
             角度P + 速度前馈 → 速度限幅 → 速度PI
                                     |
                   加速度/重力前馈 → 总力矩限幅
                                     |
                  RM_Motor::cmd/write → CAN1
                                     |
                    控制快照 → plot_task → USART1
```

附件轨迹数值表、插值公式、`trajectory_sample_at_ms()`、全局六个变量及
`trajectory_read()` 接口均保留。增加的逻辑使轨迹在未启动时停在第一个点，
避免刚上电或刚切模式就从曲线中途突跳。
新代码没有另外定义名为 `yaw`、`yaw_vel`、`yaw_acc`、
`pitch`、`pitch_vel`、`pitch_acc` 的全局变量。

组委会以后更换文件时，应保留新文件的数据/采样规则，
重新将等待/播放、时间戳发布接到其任务循环。**不能仅覆盖整个 cpp 后认为握手仍在**。
若仅提供六个全局量，需要在生产端加入一致性发布；单独声明 `volatile`
不能保证六个量属于同一时刻。

## 3. 分支使用与编译

从已经推送的分支获取代码时：

```powershell
git fetch origin
git switch --track origin/feat/trajectory-tracking
git submodule update --init --recursive
cmake --preset Debug
cmake --build --preset Debug
```

如果当前只有本地分支，不执行上面的远程切换，直接在本地
`feat/trajectory-tracking` 中编译。是否已成功推送以交付消息为准。
不要把变更覆盖回 `main`；审阅和实机测试后再决定是否合并。

`applications` 已经位于原工程头文件搜索路径中，无需添加附件 README
拼错的 `applicaitons/`。工程使用 C++17，满足附件 `constexpr` 遍历的要求。

轨迹任务静态栈 256 word（1024 B），绘图任务静态栈 512 word（2048 B），
不占用原来的 15 KB RTOS heap。原生优先级分别为 4、1；控制任务仍为 6。
新增任务写在 CubeMX 的 USER CODE 区；不要再在 CubeMX 重复创建同名入口任务。
重新生成后检查 `INCLUDE_vTaskDelayUntil=1` 仍然存在。
原控制任务栈为 512 word，实机需查看栈高水位和实际执行时间。

## 4. 遥控器操作

| 右拨杆 | 左拨杆 | 行为 |
| --- | --- | --- |
| 下 | 任意 | 零力矩；遥控在线时清除故障并允许下一次进入轨迹 |
| 中 | 下/中/上 | 保留原 IMU 联动模式，B 比例为 0.5 / -1 / 3 |
| 上 | 下或中 | 保留原复位模式 |
| 上 | 上 | 新轨迹跟踪模式 |

上电后先将右拨杆置下，再将左右拨杆都置上。
控制器先用 2 s 五次多项式从当前位置靠近第一个点：
yaw=0.314159 rad（18°），pitch=-0.523599 rad（-30°）。
两轴误差均小于 0.03 rad、速度均小于 0.15 rad/s 并持续 200 ms，
才允许轨迹开始。6 s 内无法完成对齐则退出输出并报故障。
起点与终点的目标速度、加速度为零；进入时电机本身应接近静止。

播放周期 680 ms，yaw范围±22.5°、pitch范围±30°。
附件的 `RANGE_DEG` 为总跨度，因此配置值为 45 和 60。
峰值速度约 7.148648、8.308258 rad/s；角度、速度、加速度单位分别为
rad、rad/s、rad/s²。不进行度/弧度混用。

退出轨迹模式后停止播放，下一次进入重新对齐并从相位0开始。
遥控器掉线、任一电机反馈失效、轨迹停止更新或其他保护触发时输出零力矩；
故障会锁存，切到联动/复位模式也不能绕过，须先回右下档。
零力矩是卸力，不能替代有重力负载的机械制动或托举。

## 5. 必须按实物确认的参数

在 `tracking_config.hpp` 中集中配置：

| 参数 | 初始值 | 含义 |
| --- | --- | --- |
| `kMotorAZero` | 2.86164117 rad | 沿用原工程 A 零点 |
| `kMotorBZero` | 2.10692263 rad | 沿用原工程 B 零点；须确认其确实对应 pitch 的水平零点 |
| `kYawDirection`、`kPitchDirection` | +1、+1 | 正方向；如需反向，设为 -1，会同时变换反馈、速度和力矩 |
| yaw 行程 | [-0.45, +0.45] rad | 软件工作区，需按机械结构和电缆行程确认 |
| pitch 行程 | [-0.60, +0.60] rad | 软件工作区，需确保覆盖比赛轨迹 |
| 两轴最大速度 | 10 rad/s | 包含速度前馈后的总速度目标上限 |
| 两轴最大力矩 | 0.30 N·m | 包含所有前馈后的最终指令上限 |
| 两轴积分输出上限 | 0.10 N·m | 内环积分项幅度上限 |

进入模式时选择与标定零点等价的最近一圈，之后使用连续编码器角度。
这能处理编码器过±π处的数值换圈，同时避免在 pitch 机械行程外选择“角度最短路”。
此方法假定机械工作区小于一圈；不能识别断电前已经缠绕的电缆圈数。

超出配置行程时选择报错停机，不静默裁剪比赛曲线。
如果实物行程不足，应先解决机械/比赛轨迹适配，不能通过软件限制掩盖目标无法完成。

GM6020 沿用中间件的**电流控制模式**：`RM_Motors::GM6020`，
控制帧 ID 为 `0x1FE`，`cmd()` 单位为 N·m；实际电调须配置成匹配模式。
其内部满量程为 2.223 N·m，但本应用先限制为 0.30 N·m。

## 6. 控制器结构、公式和整定

每一轴独立计算，定义关节目标 q_ref、实际 q、目标速度 v_ref、实际速度 v：

```text
e_q       = q_ref - q
v_cmd     = clamp(Kp_angle * e_q + Kvff * v_ref, -v_max, +v_max)
e_v       = v_cmd - v
tau_ff    = Kaff * a_ref + Kg * cos(q)
I_trial   = clamp(I + Ki_speed * e_v * dt, -I_max, +I_max)
tau_raw   = Kp_speed * e_v + I + tau_ff
tau_cmd   = clamp(tau_raw, -tau_max, +tau_max)
```

若 `I_trial` 使含前馈的最终力矩进一步超过上限，则拒绝该次积分增量；
反向积分、能解除饱和的增量允许通过。退出模式、故障或重新开始时清零积分。
外环只有P项，不会积累角度环积分饱和；速度环初始 Ki=0。
没有直接复用中间件 PID 的内部积分，因为其限幅只作用于自身输出，
无法自动处理本应用加入前馈后的最终执行器饱和。CAN、电机单位和绘图协议仍复用中间件。

| 参数 | yaw / pitch 初始值 | 单位及说明 |
| --- | --- | --- |
| `angle_kp` | 5 / 5 | 1/s；沿用原工程角度比例参数 |
| `speed_kp` | 0.035 / 0.035 | N·m/(rad/s)；沿用原工程速度比例参数 |
| `speed_ki` | 0 / 0 | N·m/rad；按秒积分，不是每次调用直接累加误差 |
| `velocity_ff` | 1 / 1 | 无量纲；已知目标速度直接进入速度目标 |
| `acceleration_ff` | 0 / 0 | 等效惯量 kg·m²；初始关闭 |
| `gravity_ff` | 0 / 0 | N·m；pitch水平零点时可用 cos(q) 补偿，yaw通常为0 |

建议按以下顺序整定，并保留每次的参数和曲线：

1. **核对坐标与反馈**：在右下档手动小范围转动，确认实际角度、速度符号和单位，
   标定零点、验证软件行程。正误差必须产生朝目标方向的力矩。
2. **内环先行**：在小行程、低速测试条件下令外环作用较弱，
   逐步提高 `speed_kp`，观察速度响应；出现持续振荡、噪声或机械共振时退回。
   两轴分别调整，不默认负载相同。
3. **角度外环**：提高 `angle_kp` 以减小位置滞后，保证内环明显快于外环。
   角度外环过强会频繁触发速度/力矩饱和，增加超调。
4. **速度前馈**：比较 `velocity_ff=0` 和 `1` 时的RMS、峰值误差与相位滞后，
   检查前馈是否主要减少周期性跟踪误差；不要通过任意缩放改变比赛目标本身。
5. **静差与负载**：有静差再少量增加 `speed_ki`；pitch有显著重力负载时，
   先确认水平零点，辨识 `gravity_ff` 的符号和幅度，减轻积分负担。
6. **加速度前馈**：在速度前馈稳定后，以实测负载惯量估计 `acceleration_ff`。
   参考关系是 tau≈J*a；转折处误差较大且未饱和时可尝试增大。
7. **正式轨迹验收**：原始680 ms周期下记录至少10个稳态周期，比较RMS、
   最大绝对误差、转折超调、相位滞后、饱和比例、温升和运行间隔。
   若长期饱和，先确认动力学/供电/负载能力，单纯继续增加Kp通常无益。

调试阶段如获允许，可增大附件 `TRAJECTORY_PERIOD_MS` 降低难度：
速度按原周期/新周期缩放，加速度按该比值平方缩放。
最终比赛若规定680 ms，应恢复规定周期，不能把放慢后的成绩作为正式结果。
目前只有编译和逻辑测试证据，**未给出虚构的实机最优参数或跟踪成绩**。

## 7. 绘图、记录与评价

USART1：115200、8N1，PB6 TX / PB7 RX，共地。
使用中间件 Plotter 协议：`AA BB` 两字节帧头，1字节 payload长度，
随后为小端 float32 数据。本版本长度为72，总帧长75字节，无额外帧尾。
这不是普通CSV文本，也不是默认 JustFloat 帧格式；上位机应使用匹配解析器。

输出100 Hz（10 ms周期），带宽约7500 B/s，低于115200波特下约11520 B/s的上限。
控制1 kHz与绘图100 Hz分开，UART阻塞发送处于低优先级任务。
不得同时恢复原 `usart_task` 文本打印，否则会混帧或因UART忙丢帧。

| 通道 | 含义 | 单位 |
| --- | --- | --- |
| 1、2 | yaw目标、yaw实际 | rad |
| 3、4 | pitch目标、pitch实际 | rad |
| 5、6 | yaw误差、pitch误差 | rad |
| 7、8 | yaw总速度目标、yaw实际速度 | rad/s |
| 9、10 | pitch总速度目标、pitch实际速度 | rad/s |
| 11、12 | yaw最终给定力矩、pitch最终给定力矩 | N·m，关节正方向 |
| 13、14 | yaw RMS、pitch RMS | rad |
| 15 | 状态：0失能、1对齐、2等待启动、3播放、4故障 | 枚举 |
| 16 | 故障码，见下表 | 枚举 |
| 17 | 当前轨迹相位 | ms |
| 18 | 饱和位掩码：1=yaw、2=pitch、3=两轴 | 位掩码 |

只用状态3区间评价正式轨迹跟踪。状态1显示的是启动靠近曲线；
退出或故障后保留最后目标与累计统计用于排查，不应当作仍在跟踪。
RMS在控制周期按误差平方累计，每次重新进入轨迹清零；
启动对齐不参与统计。峰值误差、总采样数和饱和采样数也保存在
`tracking::read_telemetry()` 快照中，可用调试器观察。
饱和比例=`saturated_samples/samples`；RMS是累计统计，不是滑动窗口。
主机100 Hz绘图不等于1 kHz原始数据记录，尖峰评估应参考控制侧峰值统计或增加DMA记录。

| 故障码 | 意义 |
| --- | --- |
| 0 | 无故障 |
| 1 | 尚未在遥控在线时经过右下档 |
| 2 | 任一电机反馈失效（沿用中间件100 ms存活阈值） |
| 3 | 轨迹未就绪、超过10 ms未更新，或运行中意外停止 |
| 4 | 反馈或目标包含NaN/Inf |
| 5 | 实际或目标位置越过配置行程 |
| 6 | 控制周期为0或大于5 ms |
| 7 | 6 s内没有完成对齐及启动握手 |
| 8 | 正式播放时任一轴绝对误差超过0.35 rad，持续至少200 ms |
| 9 | 轨迹活动期间遥控器失联 |

力矩限幅是软件给定限幅，不代表测得的真实力矩精度。
原中间件 `CAN::send()` 不返回发送成功状态，本版本沿用该接口；
后续可增加CAN邮箱失败计数、bus-off处理与独立故障看门狗。

## 8. 软件测试与实机边界

可运行不依赖硬件的测试：

```powershell
# 使用本机的桌面C++17编译器，不要使用arm-none-eabi-g++。
cmake -S tests -B build/host -G Ninja -DCMAKE_CXX_COMPILER=g++
cmake --build build/host
ctest --test-dir build/host --output-on-failure
```

测试直接编译控制器、状态机和实际附件轨迹源，覆盖：

- 轨迹周期、速度/加速度边界和数值差分一致性。
- 启动对齐、从相位0开始、共享快照和误差RMS。
- RTOS的32位毫秒计数回绕。
- 速度/力矩限幅、加入前馈后的积分抗饱和及积分退出饱和。
- 未解锁、遥控/电机失联、轨迹过期、NaN、超期、越界、对齐超时、持续误差。

测试用单线程RTOS替身，因此没有模拟真实中断互斥、UART/CAN硬件、
电机动力学或自由落体负载。理想反馈测试中RMS接近0只是测试断言，
不是实机性能结果。实机需测量控制周期分布、任务栈高水位和稳态跟踪曲线。

## 9. 可以怎样向评委说明

“轨迹任务产生位置、速度和加速度参考，控制任务独立闭环。
角度P环修正位置偏差，速度PI环输出力矩，已知速度作前馈减小动态滞后。
速度目标和含前馈的总力矩分别限幅，内环用条件积分避免执行器饱和后积累积分。
参数按先速度环、后角度环、再前馈补偿的顺序整定。
我们同时输出目标和实际曲线、误差、速度、力矩和RMS，
使用峰值误差、相位滞后和饱和比例判断改进是否有效。”

可进一步改进：辨识两轴惯量与摩擦；补偿pitch重力；按负载调整增益；
针对共振加入滤波；用任务通知降低轨迹发布到控制的约1 ms延迟；
用UART DMA/数据缓存提高记录率；运动基座场景引入IMU与坐标变换。
任何改进都应在相同轨迹、相同负载、相同限幅下比较结果。
