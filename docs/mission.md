# 云台手动与自动任务

## 拨杆选择

| 右拨杆 | 左拨杆 | 行为 |
| --- | --- | --- |
| 下 | 任意 | 三台电机零力矩；保留开机标定，确认故障，清除自动计时 |
| 中或上 | 下 | 自动：先运行原折叠模式，7 秒后进入原循迹流程 |
| 中 | 中或上 | 手动选择原折叠模式 |
| 上 | 上 | 手动选择原循迹模式 |
| 上 | 中 | 失能，除非有原程序循迹请求 |

上电仍先把机构放在原来的最大限位/水平标定姿态，右下保持静止，完成原标定流程。
没有经过在线右下确认而直接启动自动时，会锁存 `NotArmed`，需要回右下。

“折叠模式”指原 `fold_mode` 整个流程：初始展开、有效测距触发折叠、折叠后保持 3 秒再展开。
此次没有改成“强制折叠并保持 7 秒”，也没有修改距离阈值、PID、重力补偿或运动超时。
7 秒是整个折叠模式的总时长，已经包含折叠到位后的 3 秒保持，不再额外累加。
自动计时达到 7 秒时，直接退出折叠并请求循迹，不新增完成检测来延后切换。
循迹仍先等待 IMU、调平和对齐，再进入轨迹跟踪；7 秒并非轨迹第一点开始运行的时刻。

## 模块职责

```text
applications/mission/
    mission.hpp         输入、状态和请求接口
    mission.cpp         非阻塞自动任务状态机
    mission_config.hpp  折叠阶段持续时间和控制周期保护
```

`control_task` 每周期调用 `mission::Controller::update()`，再复用原来的 `FOLD`、`TRACKING`、
`DISABLED` 分支。自动模块只请求模式，不计算力矩，不读写 CAN，也不新建 FreeRTOS 任务。
`freertos.c`、任务栈、CubeMX 初始化、Drivers 和 SP 库均不需要改动。

7 秒由 `mission_config::kFoldDurationMs = 7000U` 设置，从标定和两台 GM6020 反馈就绪、
真正进入自动折叠模式时开始，而不是从烧录、上电、下档标定或等待就绪时开始。
进入循迹前仍由原循迹模块检查 ID3、IMU 和其他保护条件。

## 切换与故障

- 正常离开左下立即回到手动映射，退出自动并清除计时；再次进入左下重新开始 7 秒。
- 右下在自动折叠和自动循迹阶段均优先失能，清除计时；再次使能从折叠阶段重新开始。
- 手动和自动控制来源切换时，即便两边都请求 FOLD，也清理旧控制器并重新初始化折叠流程。
- 自动期间 `gimbal_tracking_request_start()` 不排队、不跳过折叠阶段；手动期间保留其原功能。
- `gimbal_tracking_request_stop()` 在两种控制来源下都有效，停止锁存仍需右下确认。
- 自动运行中的遥控失联、两台 GM6020 反馈异常、原控制器故障或控制间隔超过 5 ms，
  会终止自动并锁存失能；恢复反馈或切回手动不会自动清除故障。
- 模式切换沿用原来的公共输出清理和周期末统一 CAN 发送，不额外承诺独立的零力矩帧周期。

这次只接入云台定时流程，没有修改 `rm_dipan`，也没有增加底盘行驶、隧道通过或结束区检测。
7 秒定时不能证明整车已经通过隧道；整车联调仍需另行确认安全时序。

## 调试变量

- `control_source`：`MANUAL` 或 `AUTOMATIC`，表示谁决定当前控制模式。
- `control_mode`：原 `DISABLED`、`FOLD`、`TRACKING`，表示实际运行的控制器。
- `mission_status.state`：`Disabled`、`WaitReady`、`Fold`、`Tracking`、`Fault`。
- `mission_status.fault`：`None`、`NotArmed`、`RemoteLost`、`FeedbackLost`、`ControlFault`、`ProgramStop`、`Timing`。
- `mission_status.armed`：是否已经过在线右下确认，且启动许可未因异常撤销。
- `mission_status.started_ms`、`fold_elapsed_ms`：本次启动时间和折叠模式已运行时间，后者到 7000 后保持。
- 原 `fold_fault` 和 `debug_tracking_fault` 继续用于查看对应控制器的详细故障原因。

USART1 的绘图内容和通道数未改：FOLD 保留原 6 通道，TRACKING/循迹故障保留 18 通道。
主机测试覆盖 6999/7000 ms 边界、计时回绕、右下优先、正常重入、故障锁存、程序启停和手动回归。
模式集成测试以循迹桩隔离分发器；真实循迹和 IMU 仍由独立测试覆盖，不能代替实机验证。
